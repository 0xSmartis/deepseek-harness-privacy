# Agent Note: 移除持久匿名用户 id

Status: implemented

[English](2026-08-20-remove-persistent-anonymous-user-id.md) | 中文

## Problem

harness 会在 `$DSH_HOME/.anonymous-user-id` 中持久化一个随机 UUID，并在三条独立路径中重复使用：直连 DeepSeek 请求发送 `x-deepseek-harness-user-id`，OpenTelemetry 导出附带 Resource `user.id`，`/feedback` 则在确认文本中显示该值。该值不包含账户数据，但其稳定生命周期使每个接收端都能跨会话、跨进程重启关联活动。配置 DeepSeek gateway 或遥测 collector，并不代表用户授权跨会话跟踪，但二者仍会收到同一标识符。

共享包还让代码库必须维护一种只服务于关联的行为：存储恢复、并发创建、内存回退、包不变式、消费方依赖、文档与测试。“匿名”只描述其生成方式，并不限制接收方从重复观察中推断出的信息。

## Decision

`@deepseek-ai/dsh-anonymous-user-id` 及其三个消费方均已移除。直连 DeepSeek 请求保留强制应用归因和条件性的持久会话 id，但不添加 harness 生成的跨会话用户标头。OpenTelemetry Resource 身份保留 `service.name` 与 `service.version`，但不含用户属性。`/feedback` 保留接收会话 id 与共享披露，不创建也不显示另一身份。

被移除的实现原先生成随机 UUID v4，以裸行形式存入 `$DSH_HOME/.anonymous-user-id`，按解析后的 home 路径在进程内记忆，使用排他创建处理通常的首次并发启动，并在 home 不可写时退回进程局部值。该设计避免从 hostname 或网络地址可逆派生，并支持活跃用户聚合、提供方支持与反馈关联。但这些运维用途不足以证明默认向每个已配置 gateway 与 collector 提供稳定跨会话句柄是合理的。“匿名”并不能限制接收方进行关联。

不存在读取既有文件的兼容包或迁移。旧 `.anonymous-user-id` 文件不会再被使用，可按通常方式删除。workspace 元数据、生成目录、包文档、基础配置注释与记录当前事实的设计文档都不再把该身份描述为受支持行为。

## Alternatives considered

**保留标识符但要求显式选择加入。** 这会修复默认隐私问题，但仍需为一种没有用户控制面、保留策略或已证实需求的运维便利维护包与线路/存储约定。未来若确有获授权的关联功能，应按真实需求引入最窄生命周期与目的地策略。

**改用进程级标识符。** 进程 id 会减少持久性，但仍会向提供方和遥测请求添加未披露元数据，也不能可靠对应用户或会话。模型调用属于持久会话时，现有会话 id 已能提供请求关联。

**保留未使用的兼容包或处理既有文件。** 仓库尚未发布，对该行为没有兼容承诺。保留包或迁移处理会暗示持久身份仍是受支持概念。移除后，既有 `.anonymous-user-id` 文件不会再被读取，用户可按通常方式删除。

**从 hostname、网络地址或 git remote 派生标识符。** 派生可恢复标识符，但也会把它连接到本地识别材料，并可能被逆向；这会恶化隐私属性，而不是移除跟踪能力。

**为遥测、反馈与提供方请求生成不同标识符。** 独立值会降低跨目的地关联，却保留每个目的地内未披露的稳定跟踪，并恢复三套没有用户控制面的行为。

## Verification

- 直连提供方线路测试在有、无会话 id 时都断言 `x-deepseek-harness-user-id` 缺失。
- OpenTelemetry 线路测试拒绝 Resource `user.id` 属性。
- 真实提供方与反馈组合证明已授权请求和已接受反馈都会让 `.anonymous-user-id` 保持不存在。
- 反馈包测试与 Web snapshot 只包含接收会话和当前共享披露。
- 仓库搜索与生成目录 gate 保持被删包和受支持行为缺失；本 Note 与否定测试仅为固定该保证而保留已移除名称。

## Consequences

运维人员失去提供方请求、遥测与反馈之间的自动跨会话关联。通过持久会话 id 和会话记录，仍可进行会话内关联。该变更删除一个包及其存储、并发、回退、不变式、依赖、文档与测试 surface。

移除稳定标识符本身不会让模型提示或显式启用的遥测变得私密；这些路径仍需要独立的目的地、披露、最小化与策略控制。若要重新引入跨会话关联，必须成为显式授权的功能，具有可见的目的地与用途，尽可能采用更短生命周期，并匹配留存与删除语义。仅有提供方支持便利并不足够。
